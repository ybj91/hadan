01

设计原则

对等协议

所有 Agent 可接收、发起、评估、委托任务；不设固定 Server。

异构能力

Host 的算力、网络、传感器、在线能力决定任务适配性。

按需智能

规则优先；Decision Model / LLM 都是可选的共享能力。

原则：全局可发现 ≠ 全局复制；对等参与 ≠ 多节点同时写入同一对象。

Decision、Trigger、Capability 适配器可按 Host 配置；必要的协议能力不等于本地必须运行模型。

运行职责

04

任务协议

Incremental Decomposition · 每次只拆 Head + Tail

Task T
→
Head · Unit
+
Tail · Remaining
→
Head 成功后继续 Tail

Unit 是最小调度原子，不代表计算简单；Tail 依据 Head 实际输出继续拆解。

Unit 的执行状态与选举

SUCCESS → Validate + Commit
FAILED → Retry / Re-elect / Replan
STOPPED → Verify / Stop

状态只描述尝试的结果。裁决动作：ACCEPT · RETRY · RE_ELECT · REPLAN · TERMINATE。所有循环受预算限制。

执行契约：Task → Unit → Attempt。每次尝试带独立 attempt_id、超时、授权与幂等键；同一 Unit 同时仅有一个有效执行租约。

06

Schedule / Trigger

Global TaskDefinition
全员授权复制
→
Assigned Agent
创建时选定
→
Trigger Unit
到期激活
→
New TaskRun
分布式执行
正常路径同一个 assigned Agent 周期性触发；不进行重复选举。
故障路径仅记录异常 / 疑似漏触发；v0.1 不自动迁移。迁移未来可作为普通 Task。
Schedule 的定义全局可见，但 Trigger 只分配一个 Agent。离线观察不能直接证明它未触发；本地 run_id 唯一约束不等于跨网络 Exactly-Once。

安全与执行不变量

信任链

→
Authenticate
→
Authorize

Agent 身份 ≠ 代表的用户身份；跨节点委托不得扩大权限。

执行安全

Assess
→
Reserve
→
Execute
→
Release

租约、幂等键、任务预算、操作审计；副作用不确定时禁止盲目重试。

四条不可违反的约束

01 · Exclusive Attempt一个 Unit 同时只有一个有效执行租约。
02 · Commit Before ContinueHead 结果验证并提交后才推进 Tail。
03 · Bounded Recursion拆解、选举、重试和资源预算必须有界。
04 · No Privilege Escalation多跳调用不得放宽授权。
